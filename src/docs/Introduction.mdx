# AI-UI-LIBRARY

This is a very basic ui library that not only produces a common js library for its use in web projects, but it also produces LLM instructions for use in an LLM. An approach commonly referred to as context stuffing.

## Why make your LLM learn about your library?

The biggest issue i have with with LLMs as a Frontend Developer is their code is not consistent, which means they introduces a ton of unique code.
I never want to implement the same fix across multiple projects in different ways.
By having the LLM use the UI library it keeps bugs in one place.
It will also save money over time as it does not have to keep generating Pills and Tables etc.

In an ideal world id just train / fine-tune the LLM to use my library. Quite an expensive process both time and expense wise, especially when you consistently update the library.

## Why is the library a mix of CSS and Components

This library has been designed to componentize the hard stuff (Forms, Toast, Error Handling, etc) and only use styles for the basic stuff (headers, body, typography).
Its for use on both single page websites, and multiple page web sites that use multiple React components.

Here is a typical example of most commercial component libraries. Steep learning curve, hard coded logic which is terrible for accessibility.

```JSX
<Toast></Toast>
<Container>
  <Page>
    <Card>
      <HeadingOne> Hello World</HeadingOne>
    </Card>
  </Page>
</Container>
```

My library does it this way, much simpler, not as steep a learning curve, great for accessibility.

```JSX
<Toast></Toast>
<div className="container">
  <main className="page">
    <section className="card">
      <h1> Hello World</h1>
    </section>
  </main>
</div>
```
